# 00 · 产品定义

## 一句话

**翻到哪一页，屏幕就演到哪一页；指什么，它就讲什么；问什么，它就答什么。**

纸书是主轴，视频是它的分身。孩子手里的仍然是纸。

---

## 用户

**使用者**：3–8 岁儿童，识字量有限，注意力短，手指比嘴快。

**决策者与付费方**：陪读家长。真实痛点不是"孩子不爱看书"，是**家长不会讲**——不会拓展、不会提问、讲两页就没词了。这是我们的切入角度。

**一句话价值**：让一个不会讲绘本的家长，也能陪孩子读完一整本，而且孩子还想读第二遍。

**一个已经验证的事实**：这六本书的每页底部都印着「阅读指导」和「汉字源流」——"观察画面中小满的动作，猜一猜马上要发生什么？"。**书本身就带着教案，只是没人念给它听。** 我们要做的不是另造一套内容，是把它唤醒。这句话可以直接放进答辩开场。

---

## 三条设计原则

这三条是产品的骨架，任何功能与之冲突就让路。

**一、书是主轴。**
翻页驱动视频，不是视频驱动翻页。孩子翻到第 5 页，屏幕就切到第 5 页那一段；合上书，视频停下。屏幕永远跟着书走，这个方向不能反。

**二、每一镜可溯源。**
生成的每一段都能指回原书第几页、哪块区域。这不只是答辩时点"依据"好看——它是防幻觉的唯一硬约束，也是"生成的东西还是这本书"的证据。

**三、默认安静，有边界。**
孩子专心看书时它不说话，只在被指、被问、被翻页时响应。不做无限流，每本书有屏幕预算，到点自动转纯语音。把"伤眼睛"这个最大反对意见，变成一个功能。

---

## 和别人的差别

大部分队伍会做成"拍书 → 出动画片 → 能问答"。我们的三个差异点，答辩时就靠这三条立住：

**一、页指纹，不是每帧 OCR。**
六本书是闭集，这是匹配问题不是识别问题。80ms 内认出书和页，直接读预置结构——视频跳转、事实检索、答案证据全靠它。这是整个延迟的地基，也是最容易被低估的。

**二、语义时间轴，不是视频理解。**
生成时同步产出剧本行、实体、字幕、物体框、时间戳。**328 条 query 里 79 条"找画面"、39 条"查文字/高亮"全部变成结构化查询，不碰像素。** 全赛题最巧的一个改造——把最难的任务变成最简单的任务。

**三、风格闸门，不是 prompt 玄学。**
每帧与原书页做画风相似度打分，低于阈值打回重生成。可以量化的东西才敢在答辩上说。

## Demo 黄金路径

**照命题组的脚本来，不要自己编。** 现场三分钟，跑通比跑全重要。

1. 平板立架放书旁（**一定要立架，不要手举着**，观感完全不同）
2. 拿起书 → 3 秒内认出书名和第几页 → 屏幕开始放这一页的动画
3. 翻页 → 视频无缝跟到下一页（这一步是全场的"哇"点，一定要演示）
4. **"暂停"** → 停住
5. **"找到搭了九块积木的画面"** → 视频跳到那一刻
6. **"他们在搭什么？"** → 200ms 内回答，点"依据"高亮书页上那块积木
7. **手指点屏幕上的城堡** → 锁定环确认 → 展示信息卡
8. **"查找'我又不是故意的'"** → 字幕定位 + 高亮这句话
9. 合上书 → 视频停，出一句"下次继续读"

**必须有本地兜底素材。** 现场网络一定会出问题，每年都有队伍死在这。

## 不做什么

写下来是为了防止三周后有人开始做。

- 不做无边界的拟人陪伴聊天。它是伴读工具，不是电子宠物
- 不做"任意内容实时生成"。视频是预生成的，实时只做检索和拼接（[ADR 0002](decisions/0002-实时路径不生成.md)）
- 不做通用绘本创作平台。只做"读"这一段
- 不做成人书籍。儿童场景的约束（安全、时长、语速）是壁垒不是负担
- 不在第一版做社交分享、账号体系。等主线跑通再说

## 长期想象力（写在这里，不排期）

同一套链路换成课本、博物馆展签、药盒、说明书——**把任何一张纸变成可问答的界面**。触控万物真正的商业出口在这儿，不在绘本。

二手书、绝版书扫描即得伴读，是平台化的入口。
