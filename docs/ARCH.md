# 架构与技术选型

## 一句话

离线把书变成资产包，在线只做检索、组合和轻量生成。所有"慢"的事情都在赛前做完。

## 总图

```
[平板 / 浏览器]
  摄像头 · 麦克风 · 触摸
  ├─ 页面检测 + 透视校正（端侧）
  ├─ 坐标反算：屏幕 → 纸面 → 页面归一化坐标
  ├─ VAD + 流式音频上行
  └─ PixiJS：纸偶 / 字幕 / 高光镜头 / 后台面板
        │  WebSocket（事件 + 音频流 + 帧）
        ▼
[编排层 FastAPI]
  会话状态机 · 延迟预算 · 重试 · 降级 · 事件总线
        │
  ┌─────┼─────────┬──────────┬─────────┐
  ▼     ▼         ▼          ▼         ▼
理解   生成      问答       安全      可观测
OCR   分割/修补   RAG/LLM   分类器    事件流
VLM   纸偶/视频  镜头索引   规则      耗时日志
  │
  ▼
[资产与缓存层]  Postgres · Redis · MinIO
  书资产包 / 故事图谱 / 角色卡 / 镜头索引 / 热点索引 / 会话
```

## 七条主链路

| # | 链路 | 路径 | 目标延迟 |
|---|---|---|---|
| 1 | 开书（离线） | 拍书 → OCR/VLM → 结构化 → 分层 → 角色卡 → 纸偶 → 配音 → 高光 → QA → 打包 | 不管 |
| 2 | 翻页 | 端侧抓帧 → 降采样 → ORB 特征 + 书页指纹 → 切页 | < 300ms |
| 3 | 指哪问哪 | 手指坐标 → 单应反算 → 该页热点多边形 → 命中 | < 50ms |
| 4 | 问答 | 流式 ASR → 意图路由 → pgvector 检索 → LLM → `{answer, page, bbox, timestamp}` → 高亮 | 首响 < 800ms |
| 5 | 演出 | 纸偶实时渲染（默认）+ 高光 mp4（情绪高点） | 起播 < 1.5s |
| 6 | 收尾 | 会话日志 → 护照 / 故事卡（模板 + 真实记录，LLM 只写一句） | — |
| 7 | 后台 | 每个 stage 发事件 → WebSocket → 后台面板 + Langfuse | 实时 |

## 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | React + TypeScript + Vite + Tailwind | 有人能快速改 UI |
| 渲染 | PixiJS（2D 分层纸偶）+ Three.js 仅用于少量视差 | 纸偶本质是 2D 分层变换 |
| 几何 | OpenCV.js 端侧页面检测 + 手写单应变换 | 触控准确率的关键，不交给模型 |
| 音频端 | Web Audio API + Silero VAD（onnxruntime-web） | 端侧断句，省一次往返 |
| 后端 | FastAPI + asyncio + WebSocket | AI 生态在 Python，一条长连接传所有事件 |
| 编排 | 自研轻量状态机（不套 CrewAI / AutoGen） | 要控预算、要降级、要把 trace 画进后台 |
| 队列 | Redis + RQ | 预生成任务够用，不引入 Kafka |
| 存储 | Postgres（+ pgvector）+ Redis + MinIO | 一张库搞定图谱、索引、会话、检索 |
| 模型网关 | 自写 adapter（或 LiteLLM） | 换模型、降级、限流都在一层做 |
| OCR | PaddleOCR | 中文最稳、可离线 |
| VLM | Qwen2.5-VL-7B（vLLM）或 API | 强制结构化 JSON 输出 |
| 分割 | SAM 2 / GroundingDINO + SAM，rembg 兜底 | 绘本色块干净 |
| 修补 | LaMa | 补角色背后的背景 |
| 深度 | Depth Anything V2 | 视差分层，不用很准 |
| 图生视频 | 可灵 / 即梦 API，全部预生成 | 每本 3–5 个镜头，不追实时 |
| LLM | Qwen / DeepSeek API + 本地 vLLM 兜底 | 编剧、问答、评测共用 |
| ASR | FunASR Paraformer 流式 | 中文儿童语音 + 热词表 |
| TTS | CosyVoice 2 流式 | 角色音色，首帧 < 500ms |
| 向量 | bge-m3 + pgvector | 六本书的量，不用 Milvus |
| 可观测 | Langfuse 自托管 + OpenTelemetry | 后台剧团的 trace 从这里喂 |
| 部署 | Docker Compose 单机 | 现场一台机器，不上 K8s |

## 四个关键判断

1. **触控靠几何，不靠检测。** 单应变换 + 预标注热点可以做到 99%；纯检测模型在手指、反光、阴影下 80% 就算好。
2. **视频检索靠"生成时写索引"，不靠视频理解模型。** 生成时就知道谁在哪、第几秒，直接入库，白捡的准确率。
3. **风格一致靠"复用原画"，不靠"生成得像"。** 分层纸偶是生产方式上的保证，不是抽卡。
4. **延迟靠预生成和分层反馈，不靠推理加速。** 0.8 秒先给表情和音效，完整答案 2 秒到，比把模型优化快 0.3 秒有用得多。

## 延迟预算（设计目标，不是承诺）

| 环节 | 目标 |
|---|---|
| 页面识别 | < 300ms |
| 触摸命中 | < 50ms |
| 首响应（文字 / 表情 / 音效） | < 800ms |
| TTS 首帧 | < 500ms |
| 完整回答 | < 2s |
| 场景切换 | < 1.5s |
| 高光镜头起播 | < 2.5s（已预生成） |

## 降级链

```
实时生成失败 → 播放预生成缓存
缓存失败     → 静态分层 + 字幕 + 旁白
摄像头失败   → 纯平板点击模式
网络失败     → 本地离线包
全部失败     → 播放录屏
```
