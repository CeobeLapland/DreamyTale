# 01 · 架构设计

## 一句话

**三个真模块，剩下都是契约。**

复杂度不在层数，在数据契约。契约（02）定歪了，后期必然腐化成两套系统。

---

## 五层

```
L0 感知  →  L1 事实  →  L2 检索  →  L3 编排  →  L4 输出
```

**L0 感知层**
页识别（页指纹）· OCR · 视频帧物体检测 · 指尖定位 · ASR（中英混说）。
全部要能给出"不确定"，不许硬猜。见本文「失败即降级」。

**L1 事实层**（唯一双源的一层）
PageDocument（页归一化）+ PageFact（页面事实）+ InteractionCard（交互卡）+ Shot（语义时间轴）+ InteractionScript（脚本回放）。
自动抽取与人工标注写进同一张表，只用 `source` 字段区分。**这是整个设计的地基。**

**L2 检索层**
三级召回并行 + 重排 + 分档。见下文。

**L3 编排层**
Router 决定走快路径、标准路径还是生成路径。多 Agent 流水线在这里跑，但 Agent 之间交接的是结构化产物，不是对话。

**L4 输出层**
答案文本 → TTS / 视频定位 / 字幕高亮 / 物体信息卡 / 播放器控制。**单一出口**，见铁律二。

---

## 三个真模块

抛开层不谈，实际只有三块代码：

**一、Perception（感知）**
输入一帧画面或一段音频，输出结构化的「我现在看到了什么、听到了什么」。
关键指标：页识别 p95 < 150ms，准确率 > 99%。

**二、Knowledge（知识）**
输入一个 query，输出候选 InteractionCard + 候选 PageFact。
内部是三级召回，对外只有一个 `retrieve(query, context) -> candidates`。

**三、Studio（生成）**
离线跑：分镜 → 关键帧 → 图生视频 → 配音 → 风格闸门 → 合成 + 语义时间轴。
在线**不生成**，只做检索与拼接。这是延迟的秘密。

---

## 内容理解有两条路径，别只做一条

入库时实测出来的事实，比任何推测都硬：

- **中文三本**：文本层完好，每页 60~100 字。OCR/抽取直接可用
- **英文三本**：PDF 文本层里**一个故事字都没有**。只有水印、版权页和 InDesign 导出页脚。故事文字全部栅格化在插图里

所以"结合 OCR 与 VLM"不是可选的搭配，是**按页决定**：

1. 有文本层 → 直接抽，快到毫秒级
2. 无文本层 → VLM 读图叙事，慢但唯一可行
3. 两者都拿不到 → 老实标 `needs_vision`，别假装读过了

**这个判断必须做在页级，不是书级。** 同一本书里可能既有纯插图页也有文字页。判据就是 `text_blocks` 是否为空，`make audit` 会直接报出来。

配套一件必须做的事：**页眉页脚过滤**。赛题六本书每页都印着同一句"仅供…参赛使用，请勿外传"，不过滤的话它会污染每一条检索。判据是"同一段文字出现在 50% 以上页面"，另外 InDesign 导出页脚和纯页码也要按模式清掉。

---

## 双源知识层怎么不打架

自动抽取（VLM 跑出来的）和人工标注（我们标的）会冲突。规则写死，不许商量：

**一、human 覆盖 auto，但 auto 版本保留。**
同一位置同一实体，human 那条 `version` +1 并置为有效，auto 那条标 `superseded`。可回滚。

**二、冲突不静默。**
两边说法不一致时，落进 `conflicts` 队列，答辩前人工清一遍。**宁可少一条事实，不要留一条自相矛盾的事实。**

**三、auto 也能产卡，但优先级永远低于 human。**
没有人工卡的书必须能开口说话，所以自动路径要能生成卡（LLM 自问自答 + VLM 事实）。检索时 human 卡先命中；命中不了才落到 auto 卡。**答辩时靠 `source` 字段就能说清哪条是精标、哪条是自动产出的。**

---

## 能力与知识分离

**这是通用性的唯一来源，也是最重要的一条结构性约束。**

- **能力层**只认契约不认书。六类交互是对"纸书"这种媒介的通用能力。代码里**不许出现任何书名、页号、角色名**。
- **知识层**每本书独立生成，来源可以是自动抽取，也可以是人工标注。**人工标注是可选增强，不是必需路径。**

检验方法只有一条：**拿一本没见过的新书跑一遍，代码一行不改，系统要能开口说话。** 质量差没关系，流程必须走完、必须给引导档。

配套四条兜底，缺一条就不叫通用：

1. **未知书** → 自动冷启动：拆页 → OCR/VLM → 事实 → 时间轴骨架 → 自动卡
2. **未知意图** → 走 `other` 通道接通用对话（带书内上下文），**不是回复"我做不到"**
3. **未知物体** → 开放词表检测，不限于标注过的清单
4. **未知语言** → 检测后同语言回

**为什么不在检索层做通用。** 通用性不能靠"多加几个兜底分支"，那是补丁。真正的做法是让冷启动和热路径共用同一套 schema——同一张 `facts.jsonl`，人工写完的书和自动跑完的书长一个样，下游根本不需要知道区别。这也是 [`02`](02-数据契约.md) 里 `source` 字段存在的全部理由。

**能力通用，知识模型不通用。** 六类交互对任何纸媒介成立，但 `PageFact` 的形状要按内容类型分：绘本是"角色 + 属性 + 位置框"，教材是"概念 + 公式 + 段落"。书级用 `book.json` 的 `content_type: narrative | expository` 声明，只影响抽事实的取向和证据的单位，不影响路由。

详见 [`decisions/0003`](decisions/0003-328条是样本不是规格.md)、[`decisions/0004`](decisions/0004-能力通用知识模型不通用.md)。

**四、所有条目带内容哈希。**
赛题要求"关键生成内容可复现"，这就是答案。

## 检索分档

输入是 ASR 出来的文本，一定有错字、口语、指代。

**第 0 级 · 字面 + 拼音**（<30ms）
归一化 → 字符串匹配 → **拼音匹配** → 编辑距离。儿童语音的错字大多同音，这一层能救回大量看起来没救的 query。同时挂别名表：角色昵称、颜色指代（"那个红色的球"）、方位指代（"树上那个"）。

**第 1 级 · 向量**（<80ms）
query 与 InteractionCard 的问法变体做 embedding，top-k。

**第 2 级 · 结构**
拆成 `实体 + 意图类型`（数量/原因/位置/后续/感受/识别），在 fact 库结构化查。唯一能处理"书里一共有几只兔子"这类跨页统计的。

三级并行，重排后分档：

- `> 0.85` **强答**：吐标准答案，一字不改，走快路径
- `0.5 ~ 0.85` **弱答**：要点 + LLM 现场组织语言，不跑偏但更自然
- `< 0.5` **通用**：退到 RAG（本页 fact + 现场看图）
- 都不行 **引导**：承认没懂 + 引导翻页 + 反问孩子一句

**永远不要空答。** 答错扣分，答不出只是尴尬，卡住是灾难。

**阈值必须用那 328 条脚本当校准集来调。** 目标是最大化命中、最小化**误命中**——误命中比不命中致命得多。

---

## 六类交互怎么路由

**先分类，后检索。** 这一步的顺序不能反。

328 条 query 分六类，每类走完全不同的执行路径。第一步不是检索，是判断"这句话是要我干什么"：

- `control` 播放/暂停/继续/结束 → 直接调播放器，**不检索、不生成、不出声**
- `seek` 找到某画面 → 语义时间轴的 `entities + attributes` 结构化过滤
- `search` 查找文字 → 字幕轨字符串匹配（含拼音/大小写归一）
- `highlight` 高亮 → 同上，命中后把字幕块标出来
- `touch` 点击 → 视频帧物体检测 + `objects` 里的 bbox 命中
- `qa` 问答 → 三级召回 + 分档

**误分类是最致命的错误。** 把"暂停"识别成问答，孩子会觉得这系统是聋的；把"为什么倒了"识别成控制，什么都发生不了。所以分类器要单独评测，指标是**分类准确率**，不是检索命中率。

分类器不需要大模型。规则 + 少量关键词 + 一个小的 embedding 分类器就够，因为六类的句式差异极大（`XX的画面` / `查找/高亮` / 祈使动词 / 疑问句）。**先用规则打到 95%，残差再上模型。** 这一步换来的是几十毫秒的延迟和可解释性。

**上下文能救分类。** 脚本是线性有序的，第 5 步"他们搭的什么"必然跟着第 4 步"找到积木搭好的画面"。带上 `last_kind` 和 `last_entities`，歧义句的准确率会明显上升。

## 会话状态

不是无状态问答。要维护一个很小的状态机，答辩现场的稳定性一半靠它：

`video_time`（当前播放位置）· `play_state`（playing/paused）· `current_page`（书翻到第几页）· `last_seek_shot`（上一次定位到的片段）· `last_entities` · `last_lang`（上一句的语言，决定回哪种语言）

两条规则：
1. **翻页是最高优先级事件**，会清掉 seek 状态并跳到新页的起始时间。
2. **seek 成功后，后续 qa 默认以那个 shot 为范围**，答不出来再退到全书检索。

第 2 条不是可选项，是必须实现的。实际踩过：孩子在第 2 页问"小满在干什么"，检索在全书里找最像的段落，答成最后几页的"小满在画生日卡片"——**答案本身没错，但答的不是眼前这一页**。这类错误最难被发现，因为输出看起来完全合理。

实现方式：qa 检索时先限定在 `|page_no - sess.page| <= 2`，附近没有足够候选才退回全书。当前页永远优先于"最像的那一段"。

## 两级缓存

生成是最贵、最慢、最不可控的环节。把它赶出实时路径。

**书级 · 离线**：一本书入库时跑一夜，产出全部分页动画 + 语义时间轴 + 风格参考。存盘，进 git-lfs 或对象存储。

**页级 · 实时**：现场只做「查表 + 拼接 + 定位 + 播放」。延迟从分钟级降到百毫秒级。

**预取**：检测到孩子在看第 N 页，后台预取 N+1 页的资源和可能被问到的答案。浏览器级别的思路用在绘本上，效果很直接。

现场网络挂了怎么办：**本地兜底素材必须在设备上**，这是硬要求，不是 nice to have。

---

## 失败即降级

每个环节都要有"我不确定"这个输出，并且有对应的降级动作。这是能不能上现场的分水岭。

- 页识别不确定 → 让孩子把书摆正 / 给出候选页缩略图让他点
- 指尖定位不确定 → 出锁定环让孩子确认；再不行给候选物体列表
- ASR 置信度低 → "我没听清，你是想问小熊吗？"
- 检索没命中 → 引导档，承认 + 翻页 + 反问
- 风格闸门不过 → 重生成一次，仍不过就用上一版通过的帧

---

## 多 Agent 怎么编排

不是几个 Agent 开会讨论。是一条**确定性流水线**，每步产出结构化产物，Critic 当闸门。

导演（分镜稿）→ 画师（关键帧）→ 动画（图生视频）→ 配音 → 审片（风格/安全/文字准确性）→ 伴读（问答）。

规矩三条：
1. Agent 之间**交接文件不交接对话**。产物即接口。
2. 任何一步可单独重跑，不用重跑全链。
3. 全链留 trace，含耗时、成本、种子。答辩时能"回放"整条生成链，这是很强的加分项。
