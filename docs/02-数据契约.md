# 02 · 数据契约

**这篇是硬约束。字段名不许自己起，要加字段先改这里。**

改法：提一个 PR 只动这篇，另外两个人看过再合。理由见 [`decisions/0001`](decisions/0001-预设答案走证据层.md)。

校验靠代码，不靠自觉：`python tasks.py lint` 必须零报错才能提交。

---

## 通用规矩

**命名**：结构字段一律英文 snake_case。唯一允许中文的地方是 `attributes` 的键和 `relations` 的值——那是标注员填的，用中文更快。

**ID**：`{前缀}_{书短名}_{页两位}_{序三位}`，例：`ft_zh01_p03_007`。前缀：`bk` 书、`pg` 页、`ft` 事实、`cd` 卡、`st` 片段、`tr` trace。
书短名：小写字母开头，2~12 位字母数字。命题组六本约定为 `zh01 zh02 zh03 en01 en02 en03`；新书自取，全局唯一。

**bbox**：`[x, y, w, h]`，整数像素，**原点左上**，坐标系是归一化后的页图（长边固定 1600px）。不许用相对比例，不许用中心点。

**版本**：任何条目被修改，`version` +1，旧版本不删，`status` 置 `superseded`。

**哈希**：`hash` = 该条目除 hash 外全部字段规范化 JSON 的 sha256 前 16 位。用于可复现校验。

**落盘**：
```
data/books/{book_id}/pages/p03.png          页图
data/books/{book_id}/docs.jsonl             PageDocument
data/books/{book_id}/facts.jsonl            PageFact
data/books/{book_id}/cards.jsonl            InteractionCard
data/books/{book_id}/shots.jsonl            Shot
data/books/{book_id}/narrative.jsonl        视觉叙事层（VLM 读图产物，可选）
data/books/{book_id}/aliases.json           别名表
data/queries/{book_id}.jsonl                InteractionScript（从命题组 txt 解析）
data/traces/{yyyy-mm-dd}/                   Trace
data/turns/{yyyy-mm-dd}.jsonl               Turn（对话历史）
```
标注产物（facts / cards / aliases / queries）**进 git**。生成缓存（页图、视频）**不进 git**。理由：答辩要"可审查的关键流程配置"，jsonl 正好是证据。

## 先看清现实：328 条 query 的构成

命题组给的六份 txt 脚本就是 ground truth 和需求分布，不是参考资料。`python tasks.py parse` 解析出来的实际分布：

- **control 控制** 65 条 — `播放 / 暂停 / 继续 / 结束播放`，中英混写
- **seek 找画面** 79 条 — `找到搭了九块积木的画面`、`找到灯光变暗的画面`
- **search 查文字** 20 条 — `查找文字"POPCORN"`、`查找"我又不是故意的"`
- **highlight 高亮** 19 条 — `高亮文字"Kung Fu"`、`高亮这句话`
- **touch 点击** 28 次 — `[点击] 点击积木城堡 | 暂停并展示城堡信息`
- **qa 问答** 117 条 — 占 36%

**结论：64% 的交互是检索与执行，不需要生成能力。** 这决定了排期优先级，见 [`05`](05-交付与分工.md)。

必选（【必选】标注）共 90 条，那是硬门槛，优先级最高。其余 238 条可以按覆盖率逐步覆盖。

## PageDocument · 页归一化

不管输入是 PDF 还是拍照，先归一成这个。下游不许关心来源差异。

```
doc_id          string
book_id         string
page_no         int      从 1 开始
image_path      string
width           int
height          int
source_type     string   pdf | photo
text_blocks     array    [{block_id, bbox, text, type}]
reading_order   array    block_id 排序，Z 字阅读顺序
sha256          string
```

`type` 取值：`title | body | caption | sfx | note`。

`note` 专指书里印的**教学辅助文字**——「阅读指导」「汉字源流」这类。它是真内容，但角色不同：讲的是"该怎么读这本书"，不是故事本身。故事问答要排除它，家长提示功能要用它。混在一起两头都不对。

**PDF 的特殊处理**：有文本层就直接用，没有才 OCR。多栏排版和图文混排的顺序错了后面全错。评测集是 PDF，画质比拍照好，所以评测集上的数字会高于现场——**答辩时不要把评测集的准确率当现场承诺**。

## PageFact · 页面事实

```
fact_id         string
book_id         string
page_no         int
subject         string   实体名，用书里的叫法（"积木城堡"不是"castle"）
subject_type    string   character | object | scene | action | concept | formula | passage
attributes      object   受控词表见下
relations       array    [{pred: "躲在...后面", obj: "大树"}]
bbox            [x,y,w,h]
confidence      float    0~1
source          string   human | auto
version         int
status          string   active | superseded
hash            string
```

**subject_type 分两组，按书的内容类型取用**：叙事型（绘本）用 `character / object / scene / action`；说明型（教材、科普、说明书）用 `concept / formula / passage`。理由见 [`decisions/0004`](decisions/0004-能力通用知识模型不通用.md)。

**attributes 受控词表**（不许自创键，不够就提 PR）：
`颜色 / 数量 / 动作 / 表情 / 位置 / 穿着 / 状态 / 大小 / 材质 / 形状`

值可以用自由中文，但同类实体必须统一说法。写"棕色"和"褐色"会被检索当成两回事。

**这个 bbox 有三个用途**：答案的证据锚点、触控点击的候选清单、生成时的构图参考。别标三遍。

## InteractionCard · 交互卡

**一张卡 = 一条可能的交互**。不只是问答，播放暂停、找画面、点物体都是卡。统一成一种类型，路由才不用分叉。

```
card_id              string
book_id              string
kind                 string   control | seek | search | highlight | touch | qa
intent               string   仅 kind=qa 时必填，见下方意图表
scope                string   page | book | video
langs                array    这张卡能应答的语言，["zh"] / ["en"] / ["zh","en"]
question_canonical   string   标准问法
variants             array    5~8 条口语变体，含儿童说法与中英混说
entities             array    涉及的实体名

# ---- 执行参数，按 kind 取用 ----
action               string   control 用：play | pause | resume | stop
seek_query           string   seek 用：场景描述，去语义时间轴检索
search_text          string   search 用：要检索的字幕原文
highlight_text       string   highlight 用：要高亮的文本
touch_target         string   touch 用：要点击的物体名

# ---- 答案，仅 kind=qa ----
answers              object   {"zh": {strong, weak, guide}, "en": {...}}
evidence             array    [{page_no, bbox, fact_id}]
video_anchor         object   {shot_id, t_start, t_end}，可空

priority             int      1 必答 / 2 可能被问 / 3 补漏
source               string   human | auto
version              int
hash                 string
```

**intent 受控词表**（仅 qa）：
`identify 识别 / count 数量 / locate 位置 / attribute 属性 / why 原因 / plot 情节 / predict 后续 / feeling 感受 / compare 比较 / vocab 词汇 / common 常识 / other`

**strong 为什么不许 LLM 改写**：事实型问题（几只、什么颜色、在哪）改写只会引入错误。要自然感让 weak 档承担。

**guide 为什么必须有**：评委一定会问超纲问题试探。有这一档你是"知道边界"，没有就是"卡住了"。

**langs 为什么是数组**：中文书里问英文、英文书里问中文，是赛题脚本里的实际写法。答案语言跟提问语言走。

**source 为什么允许多值**：自动冷启动也要能产卡，否则新书没法开口说话。检索时 human 卡优先，命中不了才落到 auto 卡。这是通用性的实现方式，见 [`decisions/0003`](decisions/0003-328条是样本不是规格.md)。

示例（qa · 数量类）：


## Narrative · 视觉叙事层

VLM 把书页图读成文字后的产物。**对无字绘本是唯一的内容来源**，对有字绘本是补充。

```
page_no     int
text        string   这一页发生了什么，80~150 字，只写看得见的
entities    array    出现在这一页的实体名
source      string   vlm | human
```

不叫 `PageFact` 的原因：它是**连续叙述**，不是离散事实。检索要的是段落，标注要的是事实，两者不能混。

## Shot · 语义时间轴

**生成视频时同步产出，不是事后补的。** 这是"语音查视频"能从视频理解退化成数据库查询的唯一原因。

```
shot_id         string
book_id         string
page_no         int
t_start         float    秒，相对整本书视频的绝对时间
t_end           float
script_line     string   这一镜的旁白/台词
speaker         string   旁白 | 角色名
entities        array    画面里出现的实体
objects         array    [{entity, bbox, t_start, t_end}]  点击命中用
subtitles       array    [{text, t_start, t_end, lang}]    查找/高亮用
keyframe_path   string
seed            int      生成种子，复现用
```

`objects` 的 bbox 是**视频帧坐标**，不是页图坐标。触摸点击按这个算。
`subtitles` 是**字幕轨**，`search` 和 `highlight` 全部落在这里，不碰像素。

这两条是整套方案最省事的地方：37 条检索类 query 全变成字符串匹配，61 条 seek 全变成结构化过滤。

## InteractionScript · 脚本回放

从命题组 txt 解析出来的东西。它既是评测用例，也是会话的引导顺序。

```
script_id       string   如 zh01-004
book_id         string
seq             int      1~50
kind            string   同 InteractionCard
raw_text        string   脚本原文，不许改写
required        bool     是否标注【必选】
lang            string   zh | en
audio_path      string   对应 wav
click_target    string   仅 touch：[点击] 后面的物体名
click_action    string   仅 touch：| 后面的动作
card_id         string   可空。为空说明还没建卡
```

**脚本是线性有序的，所以上下文可用。** "找到花花生日的画面"紧接着"她为什么难过"——定位结果就是下一句的语境。会话状态至少要保：`video_time / current_page / last_seek_shot / last_entities / last_lang`。

**这大幅降低了难度**：不需要应对任意乱问，只需要沿着这 50 步走稳，再对评委的临场发挥用引导档兜住。

## Trace · 全链留痕

```
trace_id        string
kind            string   answer | generate
input           object   原始输入（query 文本 / 页图 id）
stages          array    [{name, model, ms, ok}]
tier            string   strong | weak | generic | guide（仅 qa）
result          object   最终输出
latency_ms      int
output_hash     string
created_at      string   ISO8601
```

**延迟一律记 p50 和 p95，不记平均值。** 平均值会骗人，现场卡的那一下永远在 p95 里。

## Turn · 对话回合

赛题原文要求「保留包含语音和图片的多模态对话历史」。`Trace` 记的是**一次调用**，
`Turn` 记的是**一次交互**——孩子说了什么、系统看到了什么画面、回了什么、依据在哪。
两者不能互相替代：一次 Turn 可能包含多次模型调用。

```
turn_id         string
session_id      string   同一次会话
book_id         string
ts              string   ISO8601
input_audio     string   用户语音文件路径，可空（键盘输入时为空）
input_text      string   ASR 结果或直接输入的文字
input_image     string   用户点选/指到的画面帧，可空
kind            string   六类之一
tier            string   strong | weak | quote | guide（仅 qa）
reply_text      string   系统实际说出来的话
reply_audio     string   TTS 输出路径，可空
evidence        array    [{page_no, bbox}] 用于"点依据"高亮
video_time      float    这一轮结束时播放器停在哪
latency         object   {asr, route, retrieve, generate, tts, total} 毫秒，缺项留空
```

`latency` 拆开记的原因：延迟是赛题三大难点之一，只记 total 没法定位是谁慢。

## 向量索引的落盘

语义检索要存 embedding，位置固定为：

```
data/books/{book_id}/index/vectors.jsonl   每行 {chunk_id, source, page_no, model, dim, vec}
data/books/{book_id}/index/meta.json       模型名、维度、切块策略、构建时间、语料哈希
```

**语料哈希变了就必须重建**，否则向量和文本对不上，检索会给出看起来合理其实错误的结果——这是最坏的一种错。`meta.json` 里的 `corpus_hash` 就是用来防这个的。

向量不进 git（`data/books/*/index/`），但 `meta.json` 进——它是"这个索引是怎么建的"的证据。

## QueryLog · 回流样本

```
query_id        string
audio_path      string
asr_text        string
asr_conf        float
matched_card_id string   可为空
score           float
tier            string
latency_ms      int
verdict         string   ok | wrong | miss | stuck   人工事后标
```

每周清一次 `wrong` 和 `miss`。能补卡就补卡，补不了就进引导档。这是覆盖率唯一可持续的增长方式。
