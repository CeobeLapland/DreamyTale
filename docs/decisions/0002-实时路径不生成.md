# 0002 · 实时路径不生成，只检索拼接

日期：2026-11-15
参与：三人方案讨论

## 背景

赛题把"降低交互延迟"列为三大难点之一。文生视频的单镜耗时就以十秒到分钟计，无论怎么优化模型、怎么加显卡，都不可能满足"实时交互"。同时赛题还要求"关键生成内容可复现"——生成模型的随机性天然与这条冲突。

## 决定

**把生成全部赶出实时路径。**

- **书级 · 离线**：书入库时跑一整套预生成，产出全部分页动画 + 语义时间轴 + 风格参考，存盘
- **页级 · 实时**：现场只做「查表 + 拼接 + 定位 + 播放」，不调生成模型
- **预取**：识别到孩子在看第 N 页，后台提前取 N+1 页的资源和可能被问到的答案

生成时同步产出语义时间轴（剧本行、实体、时间戳、区域），使"语音查视频内容"退化为一次数据库查询。

## 代价

- **牺牲了"任意内容随时生成"的灵活性。** 只能对入库过的书做实时交互。这是刻意的取舍：赛题是六本固定书
- 预生成要占存储和时间。一本书跑一夜，六本书需要一个通宵
- 语义时间轴要在生成时同步产出，管线比"先生成再理解"复杂。但比"事后做视频检索"简单得多
- 无法对孩子临时编的问题生成对应画面，只能走引导档

## 备选

**A. 现场实时生成，靠小模型和量化压延迟。** 压不到可交互的级别，且失败率无法接受。
**B. 生成后用视频理解模型建索引。** 慢一倍，且准确率不如生成时就记下来。
**C. 不做视频，只做语音问答。** 赛题明确要求互动视频，且这是产品的差异点，不能砍。

## 什么时候该重新考虑

- 出现单镜生成稳定进入 2 秒内的方案时
- 或者：书库规模大到无法穷举预生成（比如要做 UGC 书库），需要改成"热门页预生成 + 冷门页按需生成"
