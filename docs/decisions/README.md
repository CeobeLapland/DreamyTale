# 架构决策记录

只记**改主意**这件事。五分钟能写完，别写成论文。

不写 ADR 的后果很具体：两周后有人问"当初为什么不用 X"，三个人记着三个版本，然后花一小时开会重新讨论一遍已经讨论过的事。

---

## 什么时候写

- 推翻了已经写在 `docs/01` 或 `docs/02` 里的东西
- 选了 A 没选 B，而 B 看起来也很合理
- 做了一个"以后可能会后悔"的妥协

## 什么时候不用写

- 实现细节、代码风格、变量命名
- 显而易见的唯一解

## 模板

```markdown
# NNNN · 标题（一句话说清决定是什么）

日期：YYYY-MM-DD
参与：A / B / C

## 背景
是什么问题逼着我们做选择。不超过五行。

## 决定
我们选了什么。一句话。

## 代价
这个选择放弃了什么。**这部分必须写**，没有代价的决定说明没想清楚。

## 备选
还考虑过什么，为什么没选。

## 什么时候该重新考虑
写一个可观测的条件。例："当标注量超过 2000 张卡时"。
```
