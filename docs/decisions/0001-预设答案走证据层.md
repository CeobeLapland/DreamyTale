# 0001 · 预设答案走证据层，不走查表

日期：2026-11-15
参与：三人方案讨论

## 背景

评测会给我们几本书的 PDF 和一批交互问题。直觉做法是人工标一份"问题 → 答案"的对照表，现场查表命中就念。但输入是语音，ASR 出来有错字、有口语、有指代（"那个红色的球"），而且评委会临场换说法。硬查表在这种输入上会大面积漏命中，而且答错了比答不出更难看。

同时我们还要有"扫任何一本书都能用"的通用能力。两套系统并行，三个人维护不动。

## 决定

**人工标注不做成问答对照表，做成"高质量证据"**：PageFact（页面事实）和 InteractionCard（交互卡）与自动抽取的结果共用同一套 schema、同一个索引，只用 `source: human | auto` 区分信任权重。

检索不是精确匹配，是三级召回（拼音/字面 → 向量 → 结构）+ 分档降级。

## 代价

- 前期 schema 设计成本高。字段定歪了要返工全部标注，所以我们把 [`02-数据契约.md`](../02-数据契约.md) 定为硬约束，改它要走 PR
- 标注比"写问答对"慢一点，因为要标坐标。但这个坐标同时是触控识别的候选清单，等于少标一遍
- 多一层检索，链路比查表长。用两级缓存和预取补回来

## 备选

**A. 直接查表 + 模糊匹配。** 快，但变体一多就废，且无法回答跨页统计类问题（"一共几只兔子"）。
**B. 完全靠 LLM 现场作答。** 灵活，但事实型问题会编，而且延迟不可控。赛题要求正确率 0.60，靠 LLM 裸答风险太高。
**C. 两套系统并行。** 通用一套、预设一套，现场按书切换。三个人维护不了，且答辩时"哪些是背的"说不清。

## 什么时候该重新考虑

- 标注量超过 2000 张卡，人工维护成本失控时
- 或者：现场发现误命中率长期高于 10%，说明变体覆盖策略有问题
