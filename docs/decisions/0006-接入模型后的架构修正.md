# 0006 · 接入模型后，主干不动，补四个接口

日期：2026-11-16

## 背景

前四篇 ADR 都在讲"不要为了 328 条把系统做成应答机"。但实现走到 M1 时，我一直把"零依赖、clone 即跑"当默认优先级——这在骨架期是对的（能立刻验证、不卡在装包上），但被当成了目标就是错。

结果是：知识层用规则硬凑，凑了三次全失败（见 0005），然后才回头问"要不要接模型"。顺序反了。模型不是可选项，是这个系统的组成部分。

## 决定

**主干保留，不重写。** 下面四样在接模型后都不用改，因为它们描述的是"系统怎么想"，不是"谁来干活"：

- **六类路由**：模型只负责听懂，不负责决定做什么。分类留在本地——快、可控，且不会因为模型抽风把"暂停"执行成问答
- **Shot 语义时间轴**：模型要产出的东西，契约早就定死了
- **双源 + 三档降级 + 单一出口**：模型输出是"某个档位的候选"，不是最终答案
- **audit / eval 方法论**：换了模型之后更需要它来判断是变好还是变坏

**补四个接口，四个都是真缺：**

**一、模型接入层**（`tools/llm.py`）
key、重试、超时、流式、缓存、计量，六件事集中在一处。协议用 OpenAI 兼容格式，通义/智谱/Kimi/DeepSeek/OpenAI/vLLM 全都吃这一套，所以不写供应商适配器。配置走环境变量，不进代码。
缓存键是请求内容的哈希——顺带解决了"生成内容可复现"这条赛题要求：同样的输入第二次走缓存，结果必然一致。

**二、对话回合实体**（`Turn`）
赛题原文要求"保留包含语音和图片的多模态对话历史"。原来的契约里只有 `Trace`（一次调用的留白），没有 `Turn`（一次交互的语义记录）。这是硬需求，之前漏了。

**三、向量落盘位置**
第 1 级向量召回在设计里写了很久，契约里却没有任何地方存 embedding，也没有重建策略。要加语义检索，这一条必须先进契约，否则索引会散在脚本里。

**四、流式链路**
延迟是赛题三大难点之一，"等全部生成完再返回"必输。ASR 边听边出、TTS 首句先出、LLM 边生成边吐——架构里现在连"流"这个概念都没有。`llm.chat_stream()` 是第一个落点。

## 代价

- 有模型依赖了，就不再是"clone 即跑"。但 `lint` / `route` / `timeline` / `eval` / `audit` 仍然零依赖，只有真正要模型的那几条路径需要配置
- API 花钱、有配额、会抖动。所以必须有缓存和降级：模型不可用时退回规则路径，宁可答得笨，不可整站挂掉
- 延迟变长。所以三档并存的顺序不能乱：卡命中（毫秒）→ 向量检索（百毫秒）→ 生成（秒级）

## 备选

**给每家供应商写适配器。** 没必要。OpenAI 兼容格式已经是事实标准，多写一层只会多一处出错。

**继续零依赖硬凑。** 0005 已经把这条路走死了三次。

## 什么时候该重新考虑

- 如果某家供应商的能力（比如视频理解、语音克隆）是 OpenAI 兼容协议表达不了的，再为它单独开一个模块，而不是改通用层
- 如果缓存命中率长期低于 30%，说明调用参数里混进了时间戳之类的易变量，得清掉
