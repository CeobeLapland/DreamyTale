# 0004 · 能力通用，知识模型不通用

日期：2026-11-15

## 背景

拿一本高中化学教材（130 页扫描件，无文本层）跑了一遍冷启动。结果是：

- 页识别 / 翻页跟随：✓ 130 张页图都在
- 查文字 / 高亮：✗ 没文本层，需要 OCR
- 问答：✗ 既没文本也没卡

前者是可预期的前置缺失，补 OCR 就行。但往下想一层会发现一个更麻烦的问题：**就算 OCR 补齐了，这套东西也答不好一本化学书。**

因为 `PageFact` 的模型是照着绘本设计的——"实体 + 属性 + 关系 + 位置框"。小熊是棕色的、躲在树后面、框在第 3 页某个坐标里。这个模型套到教科书的正文段落上，粒度完全是错的：一段讲氧化还原反应的文字，没有"颜色""表情"，它的价值在概念之间的关系，不在它占了哪块像素。

## 决定

**六类交互能力（control / seek / search / highlight / touch / qa）对所有内容类型成立，不改。**
用户想"跳转""查原话""点开看看""问一句"，这些是纸媒介的通用动作，跟书是故事还是教材无关。

**知识模型按内容类型分型，改 `subject_type` 的取值域：**

- `character` `object` `scene` `action` —— 叙事型（绘本、故事）
- `concept` `formula` `passage` —— 说明型（教材、科普、说明书）

书级用 `book.json` 里的 `content_type: narrative | expository` 声明，不进主契约（它是元信息，不是标注产物）。它只影响两件事：抽事实时的 prompt 侧重，和回答时"证据"的单位（绘本是页，教材是段落）。

**证据锚点不动。** 不管是绘本的一只熊还是一段化学推导，最终都要落回"第几页、哪一块"，否则溯源和防幻觉就失效了。

## 代价

- 事实抽取要写两套 prompt，标注规范也要分两版。多一份维护成本
- `content_type` 判错了，抽取方向整个跑偏。所以它必须人工确认一次，不能全自动
- 说明型内容的"事实"密度远高于绘本，同一套索引在教材上会大一个量级，检索要重新调

## 备选

**只做叙事型，教材场景放弃。** 老实说作为比赛策略这是对的——六本书全是绘本。但我们说的是"把任何一张纸变成可问答的界面"，那就得承认纸有很多种。写在这里是为了以后不装作没想过。

**一开始就做通用知识图谱。** 理论上正确，实际是把两周的活变成两个月。不做。

## 什么时候该重新考虑

- 如果发现说明型内容需要的不是"另一种 subject_type"，而是完全不同的数据结构（比如公式要存 LaTeX、图要存拓扑关系），那就该另开一张表，而不是往 PageFact 里塞
- 如果 `content_type` 自动判定准确率长期低于 80%，说明这个二分法本身有问题

## 顺带记一件事

扫描件跑出来的结果是"能力清单里两条 ✗"，不是"整个系统崩了"。这个行为要保住：**任何书进来，系统都要能明确说出自己会什么、不会什么。** 含糊地全部返回失败，比明确地报缺更糟——尤其在现场，评委问一本没见过的书，答"我读不进文字，只能认页和放动画"，比答"这个我做不到"强得多。
