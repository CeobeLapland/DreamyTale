## 三条铁律

违反这三条，项目会在第三周开始崩。崩的方式很具体：三个人各写一套字段，最后拼不起来。

**一、数据先于代码。**
新能力先改 02 的 schema，评审过再写代码。不许在代码里临时加字段再回头补文档。

**二、单一出口。**
所有对外结果（评测接口、Demo 响应）从同一个 adapter 出。业务代码里不许拼输出格式。

**三、可回放。**
任何一次生成、任何一次回答，事后都要能用同样的输入重跑出同样的结果。做不到就说明有状态没落盘。

## 黑话表

统一叫法，避免三个人说同一件事用三个词。

- **页指纹** — 不用 OCR，靠图像特征直接认出「这是哪本书第几页」。延迟地基
- **PageFact** — 从一页里抽出来的一条事实（实体 + 属性 + 关系 + 位置）
- **InteractionCard / 交互卡** — 一条可能的交互。**不只是问答**，播放暂停、找画面、点物体都是卡
- **六类** — control 控制 / seek 找画面 / search 查文字 / highlight 高亮 / touch 点击 / qa 问答
- **确定性执行** — 六类里除了 qa 的 211 条，不需要生成能力，只需要检索和执行。占 64%
- **脚本回放** — 命题组 txt 里那 328 条是线性有序的，评测按脚本走，上下文可用
- **双源** — 自动抽取（auto）和人工标注（human）写进同一张表，只用 source 字段区分
- **证据锚点** — 答案对应的书页坐标。答辩时点「依据」高亮的那块
- **视频锚点** — 答案对应的时间轴区间。用于「跳到小熊出现的地方」
- **语义时间轴** — 生成视频时同步产出的结构化轨道（剧本行 / 实体 / 字幕 / 物体框 / 时间戳）
- **强答 / 弱答 / 引导** — 问答的三档答案。见 03
- **两级缓存** — 书级离线预生成 + 页级实时编排。见 01
- **风格闸门** — 生成帧与原书页画风相似度低于阈值就打回重生成
- **覆盖率** — 评测集中能被交互卡正确响应的比例
