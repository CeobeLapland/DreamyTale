# 04 · 评测方案

赛题给了三个维度：交互延迟、生成质量、回答正确性。我们再加四个自己能用的。**能不能量化，决定答辩时说的是事实还是形容词。**

---

## 先算清楚一笔账

328 条里 **211 条（64%）是确定性执行**：control 65、seek 79、search 20、highlight 19、touch 28。这些做对了就是接近 1.0，不需要生成能力，也不需要 LLM。

剩下 117 条 qa，靠交互卡命中就是接近 1.0，靠通用路径大概 0.6。

所以正确率大致是：

`(211 × 执行准确率 + 117 × (覆盖率 × 1.0 + (1 − 覆盖率) × 0.6)) / 328`

**这个算式决定了排期：先把 211 条做扎实，再谈 qa 覆盖率。** 211 条做到 90%，就有 57.9% 的地基；qa 覆盖 60% 再加 30%，合计 87.9%。反过来先做生成，地基是 0。

真正的杠杆有两个，按顺序：**执行类的准确率**，然后 **qa 的覆盖率**。

## Golden Set 怎么建

**好消息：不需要人工建评测集。** 命题组的六份 txt 就是 ground truth，`python tasks.py parse` 已经解析成 328 条 `data/queries/*.jsonl`。

**第 1 步 · 补 gold 标注**
每条 query 标一个 `gold_card_id`（该由哪张卡响应）。标不了就标 `gold_tier: "generic"` 或 `"guide"`。
这一步同时会暴露"我们还没建这张卡"，是标注清单的直接来源。

**第 2 步 · ASR 只用来测语音链路**
音频的作用不是告诉我们问什么（txt 已经写了），而是测 ASR 在儿童/混说语音上的准确率。把 ASR 结果和 `raw_text` 比对，得出一个独立的 ASR 准确率指标。

**第 3 步 · 混说变体**
中文书里有 `What happened?`，英文书里有 `为什么不喜欢？`。每类挑几条塞进卡的 `variants`，测跨语言。**这不是作弊**，脚本本来就这样。

**第 4 步 · 冻结**
打 tag `golden-v1`，之后不许改。评测集自己会漂移，就没有意义了。

## 指标

**主指标（赛题要求的三项）**

- **响应正确率** — 328 条里 `verdict == ok` 的比例。**按 kind 分桶看**，六类各自的数字比总分有用得多
- **交互延迟 p50 / p95** — 从语音结束到首字出声。**只记 p95，平均值会骗人**
- **生成质量** — 人工评 5 分制三档：风格一致性、叙事连贯性、音画同步。每本书抽 5 页评

**我们自己加的（答辩时的差异化）**

- **分类准确率** — 六类路由分对没有。**这是最容易崩的一环**，误分类比检索不中更致命（把"暂停"当问答，孩子会觉得这系统聋了）
- **执行准确率** — 211 条确定性执行里，动作真的做对了的比例。seek 看时间误差 < 3 秒，search/highlight 看命中的字幕块对不对
- **qa 覆盖率** — 有对应交互卡的 qa 比例。低于 0.6 说明白干
- **误命中率** — 命中了但答错的比例。**这个比不命中致命**，阈值要按它来调
- **证据完整率** — 有 `evidence` 且 bbox 有效的答案比例。防幻觉的硬指标
- **风格相似度** — 生成帧与原书页的 CLIP/DINO 相似度均值，风格闸门就是这个数
- **引导档触发率** — 太高说明知识不够，太低说明没有边界感，20% 上下比较健康

## 两套基准，分开看

意图路由（`python tasks.py route`）跑两个集合，数字要分开报，混在一起就是自欺欺人。

**脚本基准 · 328 条**
目标是 100%，这是底线不是成绩。这些句子是从命题组脚本里抄的，格式规整、句式固定。跑不满说明路由有硬伤。
当前：328/328。

**口语基准 · `data/eval/paraphrase.jsonl`**
用手写的口语变体，**故意不用脚本里的句子**：`放吧` `他为啥要跑呀` `戳一下那个机器人` `Show me the part where the castle falls`。
当前：51/51。

但这个 100% 要打个折——**这 51 条是我自己写的，写的时候知道规则长什么样。** 它证明的不是"已经通用了"，而是"没有明显的规则漏洞"。真正的考试是答辩现场评委随口问的那几句，所以：

- 这 51 条只能增不能改。改一条就等于把答案抄进考卷
- 每跑一次红队预演，把没分类对的句子原样加进去
- 三个月后这个集合里应该全是别人问出来的句子，不是我们编的

**这条纪律比任何指标都重要。** 一个能自己改考卷的评测集，等于没有评测集。

## 回归怎么做

**每次改动跑一遍，不许凭感觉。** 一条命令，出报告。

```
python tasks.py route             # 意图路由的两套基准
python tasks.py eval              # 全量 328 条（待实现）
python tasks.py eval --cat qa     # 只看某一类
python tasks.py eval --fast       # 抽 50 条，改代码时高频跑
```

报告里必须有：总分、六类分开的分数、p95 延迟、和上一次的差值、以及**所有退化的 query 明细**。最后一项最重要——总分涨了但 seek 掉 10 个点，你不看明细就发现不了。

CI 里挂 `eval --fast`，掉了就拦。三个人并行改代码，没有这个必然互相踩。

## 红队预演

**这是唯一能在答辩前发现系统性盲区的方法。**

找三个人扮评委，**不给资料**，随机问 50 个问题。全程录音。

- 第一轮：刚标完第一本书时跑。大概率一半答不上来，很正常
- 第二轮：全部标完、Demo 跑通后跑。目标命中率 80% 以上
- 第三轮：答辩前一天。只问刁钻的，专门练"卡住了怎么办"

每轮记三类：答错的、答偏的、卡住的。**答偏的最危险**——它说明检索命中了错的卡，比不命中更难发现。

## 现场保底

评测在机房跑，答辩在现场跑，两回事。分开准备。

**评测模式**：批量、离线、可重试。允许慢，必须准。输出严格按赛题接口格式，一个字段都不能少。

**现场模式**：单条、实时、不可重试。速度优先，宁可给引导档也不要卡住。

**兜底清单**（缺一项都可能翻车）：
- 本地视频素材完整，断网也能走完黄金路径
- 页识别失败时的手动选页入口（不丢人，丢人的是卡死）
- ASR 连续两次失败后自动转文字输入
- 现场前 30 分钟跑一遍全流程，别信"昨天还好好的"

---

## 答辩时怎么说数字

不要报"准确率 87%"这种孤零零的数。报三件事：

1. **这个数是在什么条件下测的**（328 条命题组脚本，含混说与 ASR 错字）
2. **最差的类别是什么**（主动暴露弱点，比被问出来强十倍）
3. **下一步怎么补**（说得出路径，说明你真的理解系统）

评委会记住的是第二点。敢说自己哪里不行的人，通常是真的懂。
