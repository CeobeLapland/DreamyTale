# 05 · 交付与分工

## 赛题要交什么

四项材料，缺一项不进一等奖候选。**按倒排期做，不要按顺排期**——最后两周一定不够用。

**a. 可运行 Demo + 5 分钟演示视频**  
网页或平板。演示视频要提前剪，不要等最后一天录。**视频是唯一能反复打磨的交付物**，值得花两天。

**b. 项目说明书**（建议 ≤20 页）  
需求分析、系统架构、核心算法、数据与模型来源、主要功能、测试结果、局限性。  
好消息是：这套文档基本就是说明书的草稿。00 出需求，01 出架构，02 出数据，04 出测试结果。**从第一周就开始攒，别最后一周写。**

**c. 源代码或可审查的关键流程配置**  
我们交源码。另外 `data/books/*/facts.jsonl` `cards.jsonl` 本身就是"关键流程配置"，是最好的可审查证据——说明哪些是精标的、哪些是自动的。

**d. 素材来源清单 + 知识产权承诺书**  
风格 LoRA 的训练图来自赛题授权绘本，这一条要老实写明。老实写不扣分，藏着被问出来才扣分。

## 三个人怎么分

按"三个真模块"切，不按层切。一人一块，接口靠 [`02`](02-数据契约.md) 对齐。

**A · 感知与后端**  
页指纹（这是最高优先级，第一周就要出数）· OCR/检测接入 · 三级召回 · ASR/TTS 接入 · 评测 harness 与 CI。  
产出验收：页识别准确率 > 99%、p95 < 150ms；`python tasks.py eval` 能一键出报告；**六类路由在口语基准上不掉点**。

**B · 生成与美术**  
分镜稿 · 关键帧 · 图生视频 · 风格闸门 · 配音与音效 · 语义时间轴产出。  
产出验收：单页端到端跑通；风格相似度有数；全链 trace 可回放。
**接口对接**：只要产出 `shots.jsonl`（含 subtitles / objects / 时间戳），前端和路由不用改。

**C · 知识层与前端**  
标注体系与工具 · 交互卡生产 · Demo 前端 · 答辩材料统稿。  
产出验收：第一本书端到端可答；Demo 黄金路径能走完；**拿一本没标过的新书能跑通冷启动并开口说话**。

**全员共担**：标注（C 一人标不完，A/B 每周各出半天）· 红队预演 · 演示视频。

## AI 怎么用

三个原则，写下来是因为很容易滑向"AI 干的，我不知道"。

**一、AI 不背锅。** 任何 AI 产出（预标注、代码、文案）必须有人 review 过才算完成。谁 review 谁负责。

**二、AI 干"量"，人干"判断"。** 预标注、批量改写、样板代码、素材整理交给 AI。判断"这个答案对不对"、"这段动画好不好看"必须是人。这两件事 AI 现在做不好，而且做错了很难被发现。

**三、AI 的产出要能回滚。** 一律落到文件、进 git、有 diff。不接受"在对话里改好了"。

**最划算的三个用法**：VLM 预标注（省一半标注时间）· 评测报告的分析（328 条明细人看不过来）· 项目说明书的初稿与润色。

## 里程碑

倒排。每个 M 都有明确的"能演示什么"，没有可演示物的里程碑不算达成。

**关键排期原则：先用占位视频把 64% 的交互做通，再换成真视频。**

**第二条：模型接入层先于一切模型功能。** 所有调用走 `tools/llm.py`，换供应商不改业务代码。本地小模型先跑通链路，再换云端大模型提质——顺序反了会一直卡在"没法验证"。
328 条 query 里有 211 条（control / seek / search / highlight / touch）根本不需要生成能力。只要 `shots.jsonl` 的契约在，视频用任何占位片段都能把播放器、路由、检索、点击全部打通并计入正确率。生成侧并行替换，不阻塞。

**M0 · 地基**（第 1 周）
六本 PDF 拆页入库、页指纹、`python tasks.py parse` / `python tasks.py lint` 跑通、`python tasks.py eval` 骨架。
**能演示**：拿书对着摄像头，屏幕立刻显示"第 3 页"。
（已完成：`parse` / `lint` / `ingest --all` / `route`。六本 120 页已入库，见 `data/books/`）

**M1 · 播放器与六类路由**（第 2 周）
占位视频 + `shots.jsonl` + 分类器 + control/seek/search/highlight/touch 五条路径。
**能演示**：播放、暂停、找画面、查台词、高亮、点物体全部走通——视频还是色块拼的。
（已完成：`timeline` / `executor` / `eval`。控制 100%，中文书找画面 86%，见 04 的基线）
**这一步拿到的分数已经过半，而且几乎不依赖生成质量。**

**M2 · 真视频 + 一页闭环**（第 3~4 周）
只做一页：OCR → 剧本 → 关键帧 → 图生视频 → 配音 → 合成 + 语义时间轴自动产出。
**能演示**：一页纸变成一段 20 秒动画，替换掉 M1 的占位。先窄后宽，不要贪。

**M3 · 知识层**（第 4~5 周）
六本书 facts + 卡（117 条 qa 优先，90 条必选优先）、三级召回、ASR 接入。
**能演示**：问一句，200ms 出答案，点"依据"高亮。

**M4 · 全书 + 打磨**（第 6~7 周）
六本书预生成跑完、翻页跟随、红队两轮、延迟优化、兜底素材、演示视频拍摄。
**能演示**：断网也能走完黄金路径。

**M5 · 交卷**（第 8 周）
说明书定稿、材料齐备、答辩演练三遍。
**能演示**：8 分钟答辩完整走一遍，不超时。

## 风险清单

按"发生了会怎样"排序，不按概率。

**一、生成质量不可控**（高）
文生视频的一致性天然不稳。对策：两级缓存把生成赶出实时路径；风格闸门打回重生成；接受"不是每页都完美"，挑最好的 5 页做演示。

**二、标注没按时完成**（高）
对策：优先级三级、砍 `priority 2` 不砍复核、AI 预标注。**这条是小团队最容易翻车的地方。**

**三、现场网络/设备故障**（中高）
对策：本地兜底素材、手动选页入口、提前 30 分钟全流程彩排。

**四、过度拟合 328 条**（中，且最隐蔽）
因为指标会很好看，所以没人会发现。对策：每种能力都必须对"没见过的书"成立。验收方式是**拿一本新书跑一遍、代码不改**。见 [`decisions/0003`](decisions/0003-328条是样本不是规格.md)。

**五、三个人做岔了**（中）
对策：02 是硬约束、每周一次 30 分钟对齐、接口变了必须改 02。

**六、答辩超时**（中）
5 分钟陈述，讲不了架构图。对策：三遍演练，砍到只剩痛点 + 三个亮点 + 一段 demo。

## 每周节奏

- **周一 30 分钟**：对齐接口和本周目标。只聊"谁卡住了"，不聊进度汇报
- **周三**：`python tasks.py route` + `eval` 跑一次，看有没有退化
- **周五 60 分钟**：红队或互评。一个小时，比各自埋头改一周有用
- **随时**：改方案就写一篇 ADR，五句话也行。不写就等于没定
