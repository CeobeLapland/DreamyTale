# 团队分工与协作边界

本文档约定 DreamyTale 的三人协作方式、职责边界、目录归属和交接接口。

基本分工：

- A、B 两人负责后端。
- C 一人负责前端。
- 生成链路和技术选择工作组共同负责，按任务由两到三人参与，B 牵头。

## 1. 项目目标

交付一本绘本的完整闭环：

```text
绘本 PDF/图片
→ 页面与脚本解析
→ OCR/VLM 内容理解
→ 故事与分镜
→ 视频和配音
→ 网页播放
→ 点击、查找、高亮、语音问答
→ 评测结果与演示视频
```

系统必须支持第二本同级别绘本，不得把页面内容、点击坐标或问答答案写死。

## 2. 分工总表

| 工作范围 | 负责人 | 协作方式 |
| --- | --- | --- |
| 后端与平台 | A、B | 两人共同完成，按模块设置主编辑并交叉评审 |
| 前端、交互与评测 | C | C 主责，A、B 提供接口、数据和联调支持 |
| 生成链路 | A、B、C | B 技术牵头，按任务由两到三人共同实现、联调和验收 |
| 模型与技术选择 | A、B、C | B 组织评估，按任务由两到三人参与并记录理由 |

所有成员都对最终 Demo 的完整链路负责。任何一人不能因为“不属于自己的目录”而不处理阻塞问题。

## 3. 角色与决策权

### A：后端与平台

A 负责：

- 维护素材导入、单书数据包、页面与脚本解析。
- 维护统一数据契约对应的后端模型、校验器和接口样例。
- 负责任务创建、排队、进度、重试、超时、缓存和失败恢复。
- 负责书籍、场景、文字、热区、问答和评测数据接口。
- 维护服务端日志、指标采集、本地一键启动和现场环境恢复。
- 负责把三人共同产出的生成能力接入可重试、可监控的后端任务。
- 与 B 共同评审 OCR/VLM/ASR/TTS/视频模型适配器的接口和错误处理。
- 参与生成链路、模型选择和最终验收。

默认目录：

```text
backend/        后端服务、数据导入、任务系统和平台集成
contracts/      与 B、C 共同维护的数据契约
```

### B：后端与平台、生成链路技术牵头人

B 负责：

- 与 A 共同完成后端与平台任务。
- 负责选择 OCR/VLM、故事模型、文生视频、ASR 和 TTS 方案。
- 提出生成链路各阶段的输入、输出、错误码、重试条件和降级条件。
- 牵头故事改编、分镜、视觉一致性、视频合成和生成质量验收。
- 组织三人完成生成链路的实现、联调和最终演示彩排。
- 对“是否继续优化”与“何时冻结功能”提出建议，并在三人确认后执行。

默认目录：

```text
pipeline/       生成链路、分镜、视频合成和生成结果校验
prompts/        可版本化的提示词和模型配置
backend/        与 A 共同维护生成相关模型适配器和任务阶段
contracts/      与 A、C 共同维护数据契约
```

### C：前端、交互与评测

C 负责：

- 网页/平板阅读器和视频播放器。
- 上传、拍照、播放、暂停、继续和进度展示。
- 点击热区、对象信息卡、文字查找与高亮。
- 语音录制、ASR/TTS 交互、对话历史和错误提示。
- Query 音频评测工具、结果记录和演示视频录制。

C 参与生成链路，负责从用户使用角度提供反馈和验收支持：

- 从阅读器和交互流程角度评审故事、分镜、视频和配音是否可用。
- 验证生成结果能否被前端稳定播放、定位、高亮和问答。
- 参与生成质量、连续性和演示效果的三人验收。
- 把前端暴露的生成问题记录到评测结果，推动 A、B 修正。

C 不承担后端任务系统或模型适配器的主实现。C 不得直接调用模型 SDK，所有模型能力通过 A、B 提供的后端接口访问。

默认目录：

```text
frontend/       网页或平板 Demo
evaluation/     评测脚本、结果汇总和演示素材
```

## 4. 后端分工

A、B 共同负责后端与平台。每项工作设置一名主编辑，另一人负责评审和联调支持。

| 后端工作项 | 主编辑 | 共同责任 |
| --- | --- | --- |
| 素材导入、单书数据包、页面与脚本解析 | A | B 验证生成链路所需的页面、场景和脚本字段 |
| 数据契约迁移、模型与接口样例 | A | B 补充生成阶段字段、错误码和重试语义 |
| HTTP API、书籍/场景/文字/热区接口 | A | B 验证生成结果接口，C 验证消费端字段 |
| 任务排队、进度、超时、缓存和失败恢复 | A | B 提供各生成阶段的耗时、可重试性和降级要求 |
| OCR/VLM/ASR/TTS/视频模型服务端适配器 | A、B | A 负责服务封装，B 负责模型参数、输出校验和质量判断 |
| 评测指标收集、日志和现场启动 | A | B 负责生成侧指标，C 负责评测口径和结果展示 |

A 与 B 的协作规则：

1. A 为主编辑的后端模块，合入前至少由 B 评审一次；B 为主编辑的生成适配模块，合入前至少由 A 评审一次。
2. 涉及任务状态、生成阶段和降级链的改动，必须由 A、B 共同确认。
3. A、B 不能把后端联调问题留给 C。
4. A、B 每周至少共同完成一次“从导入到生成任务结束”的集成测试。

## 5. 生成链路与技术选择

生成链路和技术选择由 A、B、C 组成的工作组负责。B 负责任务拆分、技术牵头和质量标准，每项任务由两到三人参与并记录结论。

| 工作项 | B | A | C |
| --- | --- | --- | --- |
| 模型选型与提示词版本 | 主编辑，制定质量和成本标准 | 接入后端任务和配置 | 从阅读体验和交互时延角度评审 |
| 故事改编与分镜 | 主编辑，负责叙事和视觉方向 | 负责结构化、可复现和任务化 | 检查分镜在播放器中的可理解性 |
| OCR/VLM 内容理解 | 负责质量标准和样例验收 | 负责服务适配器、缓存和错误处理 | 提供热点、文字查找和问答需求样例 |
| 文生视频、TTS 与视频合成 | 主编辑，负责生成参数和质量 | 负责调用、重试、产物保存和接口 | 负责播放、同步、字幕、音频和状态展示 |
| 风格一致性与跨页连贯性 | 主编辑 | 负责自动检查数据、版本和产物可追溯 | 负责用户可见效果和评测记录 |
| 失败降级与现场恢复 | 主编辑，定义降级顺序 | 实现服务端缓存、超时和恢复 | 实现前端降级提示和手动兜底 |
| 最终生成结果验收 | 牵头验收 | 验证可调用、可复现、可监控 | 验证可播放、可交互、可演示 |

三人协作规则：

1. B 负责拆出可以独立完成的生成任务，A、C 领取实际实现或验证任务。
2. 每次生成链路改动至少经过一名非主编辑成员复核；涉及数据契约时三人共同确认。
3. 每周至少完成一次三人共同参与的端到端生成验收，不能把质量检查全部留到答辩前。

## 6. 目录所有权

| 目录/文件 | 主责 | 规则 |
| --- | --- | --- |
| `backend/` | A、B 共同 | A 负责平台总体结构，B 负责生成相关适配器；修改前双方对齐 |
| `pipeline/` | A、B、C 共同 | B 技术牵头，A 负责集成，C 负责消费反馈；同一文件只设置一名主编辑 |
| `prompts/` | A、B、C 共同 | B 牵头维护模型与提示词版本，A、C 评审变更影响 |
| `frontend/` | C | 只消费已约定的 API 数据，A、B 提供接口和联调支持 |
| `evaluation/` | C | 评测输入和结果不得包含未脱敏素材 |
| `contracts/` | A、B、C | 破坏性修改必须三人确认 |
| `docs/` | 全员 | 按文档主题维护，不覆盖他人内容 |
| `temp/` | 全员 | 本地临时数据和生成结果，不进入 Git |
| `abandoned/` | 全员 | 已废弃实验，不参与构建 |

组委会 PDF、WAV、ZIP 和评测原始数据不得提交到 Git。仓库公开可读，只能提交代码、配置、文档和脱敏后的示例数据。

## 7. 接口交接

### 生成工作组交给平台

生成能力必须封装为可调用函数或服务，输入和输出遵守 `docs/DATA_CONTRACT.md`：

```text
BookPackage + Page + QuerySet（可选）
→ PageBlock / PageFact / QaCard
→ StoryPlan
→ ScenePlan
→ VideoSegment
→ BookGenerationResult / GenerationManifest
```

三人共同对生成结果的可用性负责。A 负责把生成函数接入可重试、可监控的后端任务；B 负责生成质量、阶段错误和降级语义；C 负责确认前端能够消费生成结果。

### 平台交给 C

A、B 共同保证稳定的 HTTP 接口和事件格式：

```text
POST /api/books/ingest
GET  /api/books
GET  /api/books/{book_id}
GET  /api/books/{book_id}/capability
POST /api/books/{book_id}/generate
GET  /api/jobs/{job_id}
POST /api/interact
POST /api/qa          # 兼容别名，等价于 kind=qa
```

接口字段以 `docs/DATA_CONTRACT.md` 为准。A 是平台接口的集成责任人，B 对生成相关字段和错误语义负责。C 不读取后端内部文件，也不直接调用模型 SDK。

### C 交给全组

C 交付：

- 可运行的网页 Demo。
- 前端对数据结构缺口的反馈。
- Query 评测结果。
- 交互版和非交互版演示视频。

### 三人共同交付

以下结果不归任何单人独占，必须由三人共同确认：

- 同一本 `zh-01` 的完整生成链路。
- 第二本同级别绘本的可运行验证。
- 生成质量、交互延迟和回答正确率评测结果。
- 最终演示流程、降级预案和现场彩排。

## 8. 分支与合并规则

- 不直接修改 `origin/main`。
- 分支命名：

```text
feature/backend-*
feature/pipeline-*
feature/frontend-*
fix/<component>-*
```

- A、B 的后端改动必须由另一方至少评审一次。
- 生成链路改动必须由主编辑之外的另一名成员至少评审一次。
- 涉及 `contracts/`、任务状态、生成阶段或降级链的改动，必须三人确认。
- C 保持 `frontend/` 和 `evaluation/` 的主责；A、B 提供接口、Mock 数据和联调支持，不擅自改 C 的实现。
- 每次开始工作前先检查远端和工作区。
- 至少每三次团队反馈或连续工作轮次，检查一次 `origin/main`。
- 合并前必须至少完成：

```text
git status
相关单元测试
接口样例或页面自测
```

## 10. 完成定义

一项工作只有同时满足以下条件才算完成：

- 代码已合入对应功能分支。
- 输入、输出和错误状态符合数据契约。
- 有可复现的启动或调用命令。
- 至少完成一次真实数据或集成测试。
- 对使用者说明已知限制和降级行为。
- 后端工作由 A、B 双方确认完成。
- 生成链路至少由 B 之外的另一名成员确认可运行、可播放或可评测。
- C 负责的前端和评测不被后端或生成链路阻塞。

## 11. 当前关键路径

当前优先顺序：

1. A、B 共同完成单书数据包迁移和统一 API。
2. B 把故事、分镜和第一段视频拆成可独立完成的任务，A、C 领取实现或验证任务。
3. C 使用 Mock 数据继续完成播放器与交互壳，不等生成链路全部完成。
4. 三人基于同一本 `zh-01` 完成第一次端到端联调。
5. 第 3 天结束仍依赖人工改中间文件时，暂停新增功能，优先修复自动化链路。

## 12. 2.0 契约下的调整（待三人确认）

`DATA_CONTRACT.md` 已升到 2.0.0：书与题目分离、生成产物、知识/人工修正、统一交互协议。分工表需要跟着改口径，否则会出现“按目录分人、按产物等接口”的互相阻塞。

### 12.1 按产物分，不按目录分

| 角色 | 主责产物 | 不主责 |
| --- | --- | --- |
| A · 运行时/平台 | `backend/`、API、Job、媒体、适配器、评测 runner、启动 | 生成质量、知识内容 |
| B · 内容工厂 | `pipeline/`、`prompts/`、`data/books/*/derived`、生成质量、知识自动草稿 | 前端主体验、任务队列 |
| C · 体验/审核/评测 | `frontend/`、审核页、评测面板、演示视频 | 模型调用、生成适配器 |

### 12.2 QA / 标注归属

- B 出自动草稿（facts / cards / aliases / 热区）和质量标准。
- C 做审核页与评测面板，从阅读体验验收。
- A 负责把修正落库、版本化、通过接口暴露。
- 字幕：B 产出 `Scene.subtitles`（文本/时间/语言）；C 负责播放器渲染、开关、样式和同步；A 负责媒体与接口。
- 三人共同抽检；人工修正优先于自动，auto 保留，冲突进队列。

### 12.3 三个真正的耦合点

1. `BookPackage` + 媒体路径（A ↔ B ↔ C）
2. `Scene` 时间轴（B ↔ C）
3. `Interaction` 协议（A ↔ B ↔ C）

这三处由契约定死，其余并行。不要按“谁负责哪个目录”来拒绝改动；卡住链路的人先修。

### 12.4 兜底

如果 A/C 被卡住，B 可以接手导入器、API 骨架、标注审核页；完整前端和任务队列仍由 A/C 主责。任何接手先在群里说一声，避免重复改同一文件。

### 12.5 通用性口径

原文“支持第二本同级别绘本”改为“支持任意 PDF/照片”。验收不是“第二本也能跑”，而是“拿一本没见过的书，代码不改，能出页面、能交互、能给出能力报告”。
